## 4. State and Auth

### Auth Store (`core/store/authStore.ts`)

**Technology**: Zustand with `persist` middleware

```typescript
interface AuthState {
  user: UserProfile | null;
  accessToken: string | null;
  refreshToken: string | null;
  isAuthenticated: boolean;
  isLoading: boolean;
  _hasHydrated: boolean;
  setAuth: (user, accessToken, refreshToken) => void;
  clearAuth: () => void;
  setLoading: (isLoading: boolean) => void;
  setHasHydrated: (hasHydrated: boolean) => void;
}
```

**Storage**: `localStorage` key: `ragcx-auth`

**Persisted Fields**: `user`, `accessToken`, `refreshToken`, `isAuthenticated`

### Token Management (`core/api/axiosClient.ts`)

1. **Request Interceptor**: Injects `Authorization: Bearer {accessToken}` from Zustand store
2. **Response Interceptor**:
   - Unwraps `{ success: true, data: ... }` envelope
   - On 401: Attempts token refresh using `refreshToken`
   - Queues failed requests during refresh and retries them
   - On refresh failure: Calls `clearAuth()` and redirects to login

**Refresh Flow**:
```
401 → Check if already refreshing
  ├── Yes → Queue request, wait for refresh to complete
  └── No → Call /auth/refresh with refreshToken
         → Update Zustand store with new tokens
         → Retry original request with new accessToken
```

### Route Protection (`features/auth/guards/RouteGuard.tsx`)

| Guard | Behavior |
|-------|----------|
| `ProtectedRoute` | If not authenticated, redirect to `/login`. Show spinner while hydrating from localStorage. |
| `PublicRoute` | If authenticated, redirect to `/` (dashboard). |
| `RoleGuard` | If authenticated but role not in `allowedRoles`, show `ForbiddenScreen`. |

**Hydration Check**: All guards check `_hasHydrated` to prevent premature redirects before localStorage is read.

### Providers

- `AppProviders` — Wraps app with React Query (`QueryClientProvider`) and theme context
- `AuthProvider` — Wraps app with auth state (calls `useAuthStore`)
- `SidebarLayout` — Provides navigation sidebar, header, user profile

### Hooks Using Auth State

- `useAuth()` — Returns `login`, `logout`, `register` mutations and loading states
- `useAuthStore()` — Direct access to `user`, `isAuthenticated`, `accessToken`, `refreshToken`

## 5. Feature Inventory

### Document Upload

- **UI**: Drag-and-drop file zone, upload queue with progress, upload history
- **Flow**: `FileDropzone` → `useDocumentUpload().uploadFile()` → POST `/documents`
- **States**: `UPLOADING` → `PROCESSING` → `COMPLETED` or `FAILED`
- **Special Handling**:
  - Duplicate detection (409 CONFLICT) — shows "View Document" action
  - Upload progress tracking via Axios `onUploadProgress`
  - Polls document status every 3s until terminal state

### Status Polling

- **Implementation**: `useDocumentStatusQuery` in `useDocumentUpload.ts`
- **Interval**: 3 seconds while processing
- **Termination**: Stops polling when status is `COMPLETED` or `FAILED`

### Chat

- **UI**: Conversation sidebar, message stream, document selector, message composer, sources panel
- **Flow**: `MessageComposer` → `useChatRoom().sendMessage()` → POST `/chat/sessions/{id}/messages`
- **Query Params**: Supports `?documentId=` and `?question=` for deep linking
- **Features**:
  - Document selection (filter retrieval by document IDs)
  - Optimistic UI updates (shows user message immediately)
  - Confidence rating display (HIGH/MEDIUM/LOW with color coding)
  - Citation cards with similarity scores
  - Suggested follow-up questions (clickable)

### Suggested Questions

- **UI**: `QuestionCard` and `SuggestedQuestionsList` components
- **Integration**: Shown in `DocumentDrawer` after document selection
- **Source**: `DocumentItem.suggestedQuestions` array from API
- **Behavior**: Clicking a question sends it to chat (via query param)

### Settings

- **Sections**: General, AI Configuration, Retrieval Thresholds, Document Processing, Preferences
- **Access**: All sections visible; some forms may be admin-only (`isAdmin` check)
- **Persistence**: Updates via `useUpdateSettings` mutation (unverified endpoint)

### Role Gating

- **Roles**: `ADMIN`, `USER`, `MANAGER`
- **Admin-only Features**:
  - Upload button on documents page (`user.role === "ADMIN"`)
  - Bulk actions (delete, reprocess)
  - Settings forms (AI, Retrieval, Document Processing — unverified)

## 7. Known Problems

### Broken Layouts

1. **Sidebar not collapsing properly** — `sidebarOpen` state in `uiStore` may not persist correctly. Sidebar toggles but state may reset on navigation. (Unverified)

2. **Document drawer z-index** — The `DocumentDrawer` may render behind other elements on smaller screens. (Unverified)

3. **Chat sources panel overflow** — On narrow screens, the right-hand sources panel (`w-80`) may cause horizontal scroll or truncation. (Unverified)

### Dead Ends

1. **Login → Dashboard redirect loop** — If refresh token is expired but access token appears valid, the app may hang. The 401 retry logic may not trigger correctly. (Unverified)

2. **Upload after duplicate** — After a duplicate upload is detected, clearing the queue item doesn't re-enable uploading the same file again (same filename + size key). (Unverified)

3. **Settings forms not saving** — The `useUpdateSettings` mutation may not be wired to a working endpoint. (Unverified)

### Console Errors

1. **Hydration mismatch** — The animated gradient background (`gradient-animate`) uses random start positions which can cause React hydration warnings. The `suppressHydrationWarning` on `<html>` may not fully resolve this.

2. **Zustand persist warning** — On first load, `_hasHydrated` may not be set correctly, causing a brief flash of unauthenticated state.

3. **React Query devtools** — No devtools configured; hard to debug query state in production.

### Unused Components

1. **`ForbiddenScreen`** — Referenced in `RoleGuard` but never rendered (role checks may not be fully implemented in UI).

2. **`SessionExpiredDialog`** — File exists but not used in codebase.

3. **Dashboard components** — Several widgets (`HealthWidget`, `AnalyticsCharts`, `ActivityTimeline`) may not have real data wired.

4. **Settings forms** — Most settings forms exist but may not save to backend (`GeneralSettingsForm`, `AiSettingsForm`, etc.).

### Duplicate Code

1. **Auth state in multiple places** — Both `useAuthStore` and `useAuth()` hook access auth state. Some redundancy in login/logout logic.

2. **Document mapping** — `mapDocument()` in `documentsApi.ts` handles field mapping. Similar mapping may exist in backend responses that could be simplified.
